从随机数到一张地图

这是一个最经典的程序化地形生成演示：先用 Perlin Noise 生成连续噪声， 再用 fBm（Fractal Brownian Motion） 叠加多个尺度，最后把高度区间映射成水域、沙滩、草地、岩石与雪山。 所有运算都在浏览器本地完成。

它到底是怎么生成出来的？

下面按“随机 → 平滑 → 叠加 → 分类”的顺序拆开。

01 / RANDOMSeed 生成确定性的伪随机梯度。
02 / PERLIN对网格角点贡献做平滑插值，得到连续噪声。
03 / fBm叠加多个不同频率、不同振幅的噪声层。
04 / BIOME把 0~1 高度值切成海洋、平原与山脉。
1. Seed：为什么“随机”还能复现？

地图生成一般不用真正不可重复的随机数，而是使用 伪随机数生成器 PRNG。 同一个 seed 会产生同一串“随机数”，因此地图可以被保存成一个很小的整数，而不是保存整张像素图。

rn+1 = F(rn, seed)
在本页面里，seed 只用来打乱 Perlin Noise 的 permutation table。相同 seed + 相同参数 ⇒ 完全相同的地图。
2. Perlin Noise：把“白噪声”变成连续地形

如果每个像素都独立随机，结果会像电视雪花一样跳变。Perlin Noise 的核心不是直接随机“高度”， 而是在整数格点放置伪随机梯度向量，然后计算当前位置相对格点的方向向量，并做点积。

d = g · (p − pgrid)

为了避免格子边界出现明显折痕，经典实现使用 Ken Perlin 的 fade 曲线：

fade(t) = 6t5 − 15t4 + 10t3

再把四个角点的贡献沿 x、y 两个方向插值：

lerp(a, b, t) = a + t(b − a)

这一步让附近位置拥有相近的数值，因此随机结果不再是“砂砾”，而开始出现连续的丘陵、谷地与大片区域。

3. fBm：为什么要叠加多个 octave？

单层 Perlin Noise 往往过于光滑。游戏里更常见的是把多层噪声叠加： 大尺度层控制大陆轮廓，小尺度层补充山脊、岸线等细节。

H(x,y) = [ Σi=0n−1 ai · N(fix, fiy) ] / [ Σi=0n−1 ai ]
ai = persistencei,    fi = lacunarityi

Persistence 决定高频细节还保留多少振幅；Lacunarity 决定每一层频率增加多快； Octaves 则是总共叠几层。

4. 从高度值变成“地图”

得到 H(x,y) 后，把它归一化到 0~1，并设置若干阈值：

biome(H) = { water, H < Tsea; sand, Tsea ≤ H < T1; grass, T1 ≤ H < T2; rock, T2 ≤ H < T3; snow, H ≥ T3 }

注意：这里的颜色并不是噪声的一部分，而只是“把连续数值解释成游戏世界”的规则。 同一张高度图还可以被解释成温度、湿度、资源密度、敌人刷新概率等。

5. 岛屿模式：给噪声乘一个空间约束

纯噪声没有“地图中心应该是陆地、边缘应该是海”的概念。要生成岛屿，可以引入到中心的归一化距离 d， 再把它作为衰减项减掉：

Hisland(x,y) = H(x,y) − k · dp

这就是一个很重要的程序化生成思想：噪声负责自然感，规则负责结构感。 真正的游戏地图通常还会继续加入河流、道路、气候、可达性、任务点等约束。

6. 与代码一一对应的核心伪代码
height = 0 amplitude = 1 frequency = 1 for i in 0 .. octaves-1: sampleX = x / scale * frequency sampleY = y / scale * frequency height += perlin(sampleX, sampleY) * amplitude amplitude *= persistence frequency *= lacunarity height = normalize(height)

你可以把地图生成看成一个“场函数”：给定任意坐标 (x,y)，函数都会返回一个确定的高度值。 因此它天然适合无限地图、分块加载（chunk）和按需生成。
